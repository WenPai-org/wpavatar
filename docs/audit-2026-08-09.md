## 1. 功能、入口和数据流

- 主入口 `wpavatar.php`：加载组件、注册四个 AJAX 缓存操作、激活/停用钩子、翻译文字过滤器。
- 头像路由 `includes/core.php:Cravatar`：从用户、文章或评论取得邮箱，生成 SHA-256，替换 Gravatar 主机为 Cravatar、第三方镜像或自定义 CDN。
- 本地缓存 `includes/core.php:Cache`：在 `wp-content` 下按单站或 `site-{blog_id}` 缓存头像；读取时替换头像 URL；评论批准和资料更新时预取；WP-Cron 每日清理。
- 基础短代码 `includes/core.php:Shortcode`：`[wpavatar]`、`[wpavatar_username]` 及菜单占位符。
- 后台 `includes/admin.php:Settings`：五组 Settings API 表单和 AJAX 缓存状态/清理。
- 多站点 `includes/multisite.php:Network`：网络级设置、受控选项、导入单站设置、向站点复制、站点缓存隔离。
- 营销短代码 `includes/marketing.php:Marketing`：最新评论者、最新用户、随机用户和文章作者头像；公开页面会查询评论/用户表。
- 兼容层 `includes/wpcy-compatibility.php:Compatibility`：检测 WP-China-Yes，移除其头像过滤器并提高 WPAvatar 优先级。
- 外部依赖：WordPress HTTP API、Settings API、Cron、用户/评论查询、Cravatar/Gravatar/WeAvatar/Libravatar 或管理员指定 CDN；无 Composer 运行时依赖，无凭据。
- 停用只移除当前站点的定时事件。仓库没有 `uninstall.php`，卸载不会删除选项或缓存；本轮没有擅自增加删除逻辑。

## 2. 已确认并修复

1. **P0：多站点文件无法解析。** `includes/multisite.php` 有 12 处多余右括号，激活后加载即 fatal。共享工作区已有未提交修复，本分支复制该补丁，没有覆盖共享 WIP。
2. **P1：请求加载时修改插件目录并从公网写文件。** 原主文件在每次加载时创建/复制插件文件，`plugins_loaded` 还会下载 logo 或用 GD 生成图片。只读文件系统、原子升级及校验包环境会失败。现改为发布包必须自带静态文件，运行期不再写插件目录。
3. **P1：自定义 CDN 可造成 SSRF，缓存下载缺少大小和内容真实性限制。** 现只接受裸 HTTPS 公网主机，精确比对 host，拒绝内网/保留 IP、协议、端口、路径和用户信息；使用 `wp_safe_remote_get`、两次重定向和 2 MiB 上限，解码检查 JPEG/PNG/GIF/WebP，临时文件原子改名，并用锁文件降低同一头像并发回源。
4. **P1：设置值仅声明类型但没有 sanitize callback。** 单站 Settings API、网络保存、单站导入网络以及向站点复制均增加枚举、范围、主机、CSS class 和路径校验；网络受控选项不能再借任意 option 名覆盖其它站点配置。
5. **P1：缓存路径可指向 `wp-content` 外。** 新保存和运行时读取均限制在 `WP_CONTENT_DIR` 内，非法旧值回退到 `uploads/cravatar`。缓存文件名只接受 32/64 位十六进制 hash，尺寸限制为 16–512。
6. **P1：头像 alt 和用户名短代码可输出未转义用户显示名。** 现分别使用 `esc_attr`、`esc_html`；短代码前后缀经 `wp_kses_post`。
7. **P1：营销短代码参数可绕过后台 min/max。** 评论/用户数量限制为 1–50，头像 20–150，基础头像 16–512，避免异常大查询和文件名。
8. **兼容性：** 新站点事件从已弃用的 `wpmu_new_blog` 改为 WordPress 5.1+ 的 `wp_initialize_site`；导入前确认站点存在。代码已使用空合并运算符，文档原称 PHP 5.6 不实，最低 PHP 修正为 7.0。

## 3. 未直接改变的产品和架构问题

- **营销组件建议拆分/弃用路径：** 四个营销短代码不是头像路由核心，会公开展示用户/评论者身份，产生额外查询和多头像回源。1.9.x 保留兼容但标记 legacy；2.0 建议拆为独立扩展或默认关闭，至少经过一个版本弃用期，不直接删除已有短代码。
- **同步缓存仍可能拖慢首屏：** 锁只解决相同文件的并发，同一页面首次出现 N 个不同头像仍可能产生 N 次同步 HTTP。下个版本应改为 stale-while-revalidate/异步预热，前台 miss 直接返回远端 URL。
- **大网络“应用到全部站点”只处理前 500 个：** 当前 UI 明示操作会覆盖全部，但实现固定 `number=500`。应改为可续跑批任务并记录游标，不能简单在一次请求加载所有站点。
- **卸载策略未定义：** 选项、Cron 与缓存文件的保留/删除需显式产品选择；默认不应在未授权时删除历史数据。
- **WP-China-Yes 兼容层直接遍历全局过滤器并强制移除另一插件回调。** 保留现有行为，但建议双方改为公开 opt-out filter，避免插件更新后类名漂移和优先级争用。
- **PHPStan 缺少 WordPress stubs/配置；仓库没有正式集成测试、E2E 或 Plugin Check 配置。**
- **CI 事实：** `.forgejo/workflows/auto-label.yml` 和 `stale-cleanup.yml` 调用不存在的脚本；安全工作流因无依赖锁文件/容器文件会全部跳过。通用 PHPCS 当前报告 495 errors/88 warnings，不能写 PASS。
- **更新器冲突：** 插件 slug `wpavatar` 同时存在 WordPress.org（在线 API 2026-08-09 返回 1.9.4）与 FeiCode 真源（仓库 1.9.5），代码没有 `Update URI` 或 FeiCode updater。未来 WordPress.org 版本高于 FeiCode 时可能覆盖 FeiCode 构建。必须先决定单一发布通道并提供可验证 updater，再加 `Update URI`；本轮未擅自切断现有更新。
- **版本和发布包：** 代码仍是 1.9.5，修复未冒充已发布版本。新增可复现的 allowlist 打包脚本；正式发布前应定为 1.9.6、同步 changelog/Stable tag/插件头并验证升级。
